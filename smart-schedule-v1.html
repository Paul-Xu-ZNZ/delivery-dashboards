一、智能排期 1.0

1.1 「什么条件下能发起网申」—— 发起门禁（四条件判定）

对应问卷 Q1 / Q2 / Q3 + 补充留言。问卷揭示了一个关键事实：三个"模糊条件"的共识度差异极大，规则设计按共识度从强到弱落地。

条件问卷结论（分布）1.0 建议规则边界与差异化（来自Q6留言）
① 文书定稿
Q1：只差文书未定稿，可否排？		 先不排 18票 / 54.5%
可以排 15票 / 45.5%
默认不排，等定稿。意见接近五五开，取保守口径；把"边排边催"留作 2.0 差异化能力。 留言提出按学生类型差异化：CV/RL 零修改、光速定稿型学生 PS 大概率秒定，可放宽；"文书反复修改"标签学生严格不排。→ 建议作为 2.0 标签规则，1.0 先统一。
② 语言达标
Q2：已报名11-05雅思、暂无成绩，怎么算？		 未达标不满足 25票 / 75.8%
已报名算"在路上" 8票 / 24.2%
强共识：未达标即不满足，不排。"已报名"只是"在路上"，1.0 不计入达标。 ① 按地区差异化：英澳可先交再补语言班（港校没语言没法交）；② 学生四级/六级能佐证水平的可人工豁免；③ 留言提醒"考雅思≠考得出"（年初考到年末、解约案例），不排是安全的。
③ 核心材料齐全
Q3：只差一份在读证明，可否算满足？		 不影响发起，先排 23票 / 69.7%
材料未齐全不算 10票 / 30.3%
材料分级：关键材料缺失不排，非关键缺失可先排。表面 7 成愿意先排，但开放留言反转了口径（见下方警示）。 留言明确：在读证明是关键材料——上面有入学时间/预计毕业时间，直接影响 CV 和网申填写，先填后补会导致返工重填。
材料齐全后可由智能助手自动发起群提醒学生补件。
④ 项目开放
Q6 多条留言		 硬条件：项目开放后才允许排期。留言痛点：学校开放时间不固定——
① 晚开放（如港大文学院）：群里不停弹提醒，很困扰 → 已排期的项目延期开放时，系统应自动顺延并静默处理，减少无效提醒；
② 提前开放（如南洋理工）：被放在11月，10月根本没排上、全靠客户自己看见 → 开放提前时系统需自动前移并推送提醒；
③ 可增加"项目开放提醒"推给学生，避免想不起来看。
⚠️ 口径矛盾提示（Q3）：选择题 69.7% 选"缺在读证明不影响发起"，但开放式留言中两位老师明确反对——"雅思、在读证明都是关键材料，不能缺失""先填申请后补材料，之后还得重新修改，浪费时间"。选择题容易被"尽量别卡住"的惯性带偏，规则设计应以材料分级方案落地：关键材料清单（在读证明、成绩单、语言等）缺失即拦截，非关键材料（如文书外附件）缺失可先排并挂待办。
1.0 发起门禁总结（一句话）：文书全部定稿 + 语言达标（不含已报名未出分）+ 关键材料齐全 + 项目已开放，四项全满足才进入排期池；任一不满足 → 任务留在"待条件池"，条件满足后自动入池。

对应问卷 Q4（四选二排序）+ Q5（成功率信息是否改变排序）。

Q5：告知南洋理工近7日自动网申成功率仅15.7%（全校最低）后，排序会变吗？票数解读
不改，截止日还是第一考虑要素24（72.7%）成功率先放一边，DDL 才是硬道理

1.0 排序因子（按权重落地）：
P1 截止日临近度（轮次 DDL 距今天数，核心因子）
P2 客户风险（预警/客诉客户置顶）
P3 饥饿度（条件满足后等待时长，次级参考）
P4 成功率 —— 1.0 不作为排序因子，仅在任务卡上做提示标签（"该校近期自动网申成功率 15.7%"），避免自动踢出。
排除项（不进入排期池，Q6留言）：已拿梦校 offer 剩余申请待定、学生明确放弃某项目、已填好只差缴费。

二、系统调整完排期，自动带入调整理由

需求来源：Q6 留言 #33——"不满足申请条件的申请，能自动调整排期，不要再让我手动调整"；以及"材料标注不可用，自动群里提醒学生"。系统每次自动调整排期时，须同步写入结构化调整理由，让售后老师不用追问"为什么被挪走了"。

2.1 自动调整场景 → 调整理由枚举

理由分类触发事件调整动作 + 自动带入的理由文案（示例）
条件失效 文书定稿被撤销/重新修改"文书定稿状态被撤销，自动移出排期池，待重新定稿后恢复"
语言出分未达标"雅思/托福成绩未达项目要求，自动顺延至下一轮"
关键材料被退回/标注不可用"在读证明标注不可用，已移出排期 + 已自动在群内提醒学生补件"
项目延期开放/关闭"港大文学院延期开放，排期自动顺延至开放日；南洋理工提前开放，已前移并推送提醒"
客户侧 客户临时调整申请安排（如某校赶下一轮）"客户要求XX项目赶下一轮，排期已前移至XX日"
学生变卦只递交冲刺/保底"学生暂缓递交保底项目，已移出本轮"
学生确认网申信息极慢（海本时差/考研）"学生确认周期长，建议排期预留N天缓冲"
状态完成 已填好只差缴费"网申填写完成，待学生缴费，单独打【待缴费】标签"（Q6：填写与提交不同天，目前缺标志辨别）
已拿梦校 offer"已获梦校offer，剩余申请暂缓排期"

2.2 调整理由的三要素

  • 结构化：理由必须是枚举值（上表），不允许自由文本——与变更原因下拉枚举方案同一套思路，便于后续归因统计；
  • 可追溯：每条自动调整记录 = 调整时间 + 触发规则 + 原日期 + 新日期 + 恢复条件（"满足XX后自动恢复排期"）；
  • 可感知：调整后在话题群/任务卡同步可见，DDL 前遗漏提醒联动（#33："希望在 DDL 前提醒我，还有哪些学生没有交申请"）。

三、自定义需要调整排期的（可配置项）

问卷中"是否启用/怎么调"分歧最大的点（Q1 近五五开、Q5 有 18.2% 要人工兜底、#1 留言"能自己选择要不要智能排期吗，计划赶不上变化"），决定了 1.0 必须留足人工自定义空间：

配置模块可配置内容问卷依据
规则开关 ① 按老师/按客户粒度开启或关闭智能排期；② 语言"已报名算在路上"口径开关（默认关）；③ 排序因子权重（截止日/风险/饥饿度） Q1 五五开；Q5 18.2% 人工兜底；#1 留言
条件豁免 ① 地区差异化：英澳项目允许"语言在路上"先排（有语言班）；② 学生标签差异化："光速定稿型"放宽文书条件、"文书反复修改型"收紧；③ 非关键材料缺失先排 #17 留言（地区+标签差异化）；Q3 材料分级
人工兜底 ① 智能建议允许"采纳 / 修改后采纳 / 拒绝"三种操作，拒绝需选枚举原因；② 人工可把任务降权或置顶 Q5 "看能不能人工填写都低"

提醒策略 ① 提醒频率与渠道可调（企业微信反复提醒会引发学生/家长焦虑，#18 留言）；② DDL 前提醒阈值（提前N天）；③ 项目开放提醒推送对象（老师/学生）可勾选 Q6 #18、#5、#33 留言
视图操作 大数据量（50+、100+）下的批量拖拽与智能检索：在指定日期直接检索学生名 → 勾选数据 → 移动 Q6 #32、#43 留言

四、埋点设计

埋点目标：① 验证 1.0 四条件门禁和排序规则是否有效；② 为 2.0 差异化（标签、地区）提供数据；③ 量化"每周排期 0.5~1 小时"的提效幅度（#33 留言基线）。

埋点域事件关键字段用途
排期生成 smart_schedule_created建议任务数、命中条件明细（四条件各自状态）、生成方式（智能/人工）统计四条件拦截分布，验证门禁合理性
smart_schedule_action操作类型（采纳/修改后采纳/拒绝）、拒绝原因（枚举）、操作人、耗时采纳率是 1.0 北极星指标；拒绝原因直接指向规则迭代方向
schedule_manual_edit修改前后日期、修改理由（枚举）量化智能建议与人工意图的偏差
条件门禁 gate_blocked拦截条件类型（文书/语言/材料/项目开放）、材料细分类型、客户、项目#33 说"大部分工作是筛选不满足条件的"→ 拦截TOP类型决定自动调整优先做哪个
gate_recovered拦截→恢复的时长、恢复触发方式（自动/人工）衡量"待条件池"周转效率
自动调整 auto_adjust_applied调整理由枚举、原日期、新日期、是否群内自动提醒验证"调整理由自动带入"的覆盖率和理由分布
auto_adjust_revert自动调整后被人工改回的次数、原因调整正确率；被改回率高=规则误判
执行结果 submit_gap计划递交日 vs 实际填写日 vs 实际提交日Q6 #38：填写与提交不同天、目前无标志 → 建立偏差分布，支撑"填写/提交分离"的标签设计
ddl_miss_alertDDL前提醒发送数、命中数（真遗漏）、误报数评估提醒准确性（防打扰，#18 留言）
效率收益 ops_time_spent每次排期操作时长（上线前基线 0.5~1h/周）量化智能排期提效幅度，闭环汇报
custom_config_changed配置项、变更前后值、操作人观察自定义功能使用率，决定 2.0 做深还是收敛
埋点优先级建议：首批只埋 3 个——采纳率（smart_schedule_action）、拦截分布（gate_blocked）、自动调整被改回率（auto_adjust_revert）。这三个直接回答"1.0 规则对不对、要不要按问卷分歧做差异化"。
